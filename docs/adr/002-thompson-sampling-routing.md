# ADR-002: Thompson Sampling для адаптивной маршрутизации платежей

## Статус
Accepted

## Контекст

Платформа агрегирует несколько платёжных провайдеров. При каждой транзакции необходимо выбрать провайдера. Характеристики провайдеров — success rate, латентность, доступность — не являются стационарными: они изменяются вследствие технических сбоев, изменения правил антифрод систем или перегрузки. Задача выбора оптимального провайдера в условиях неопределённости формализована как задача многорукого бандита (Multi-Armed Bandit, MAB).

Наивные подходы неприемлемы:
- **Фиксированный провайдер** — перегрузка одного, простой остальных,
  нет failover
- **Round-Robin / Random** — не учитывают качество провайдеров, не
  адаптируются к деградации
- **Статические правила** (по типу карты, географии) — требуют
  постоянного ручного сопровождения, не реагируют на деградацию
  оперативно

Любой метод маршрутизации должен решать фундаментальную дилемму exploration/exploitation: использовать лучшего известного провайдера (exploitation) или направлять часть трафика на остальных для актуализации статистики (exploration). Фиксированный баланс здесь невозможен — оптимальное соотношение зависит от текущей неопределённости оценок.

## Решение

Принят алгоритм Thompson Sampling с мультикритериальной функцией оценки.

**Базовый механизм.** Для каждого провайдера pᵢ поддерживается бета-распределение Beta(αᵢ, βᵢ), моделирующее вероятность успеха. При выборе провайдера для каждого кандидата генерируется сэмпл θᵢ ~ Beta(αᵢ, βᵢ). Провайдеры с высокой неопределённостью (мало наблюдений) получают высокую дисперсию — это органично обеспечивает exploration без явного параметра.

**Мультикритериальная функция оценки.** Вероятность успеха является необходимым, но недостаточным критерием: мерчант заинтересован также в минимизации комиссии и латентности. Предложена взвешенная функция:

    score(pᵢ) = w₁·θᵢ + w₂·max(0, 1 - Lp95,i/LSLA) + w₃·max(0, 1 - Cᵢ/Cconfig)

где:
- θᵢ — сэмпл из Beta(αᵢ, βᵢ): стохастическая оценка вероятности успеха
- Lp95,i — 95-й процентиль латентности провайдера; p95 выбран вместо
  среднего, так как сетевые задержки имеют распределение с тяжёлыми
  хвостами — среднее скрывает выбросы
- LSLA — максимально допустимая задержка по бизнес-требованиям
- Cᵢ — комиссия провайдера
- Cconfig — максимально допустимая комиссия мерчанта
- w₁ + w₂ + w₃ = 1

Детерминированные компоненты (латентность, комиссия) добавлены в процессе разработки — изначально рассматривалась только вероятность успеха. Стохастический компонент θᵢ обеспечивает exploration; латентность и стоимость являются наблюдаемыми величинами, не требующими вероятностного моделирования.

Предусмотрены бизнес-профили весовых коэффициентов:

| Профиль | w₁ | w₂ | w₃ | Приоритет |
|---|---|---|---|---|
| Conversion-first | 0.70 | 0.20 | 0.10 | Успешность |
| Balanced (default) | 0.60 | 0.25 | 0.15 | Баланс |
| Cost-sensitive | 0.50 | 0.15 | 0.35 | Стоимость |

**Обновление параметров с затуханием.** После каждой транзакции
с результатом r ∈ {0, 1}:

    αᵢ ← max(1, γ·αᵢ + r)
    βᵢ ← max(1, γ·βᵢ + (1 - r))

Коэффициент затухания γ = 0.99 соответствует эффективному окну ~100 наблюдений. Это обеспечивает адаптацию к изменению качества провайдера без полного сброса накопленной статистики. max(1, ...) гарантирует численную устойчивость: параметры бета-распределения не опускаются ниже 1.

**Интеграция с Circuit Breaker.** При переходе провайдера из состояния Open в Half-Open выполняется частичный сброс:

    αᵢ ← max(1, αᵢ·ρ),  βᵢ ← max(1, βᵢ·ρ),  ρ = 0.1

Математическое ожидание E[θᵢ] = αᵢ/(αᵢ + βᵢ) сохраняется при умножении обоих параметров на одинаковый коэффициент, тогда как дисперсия возрастает. Алгоритм помнит историческую репутацию провайдера, но становится менее уверенным в его текущих характеристиках — это стимулирует активное исследование восстановившегося провайдера без потери накопленной статистики.

## Альтернативы

**Статические правила (rule-based routing)**

Маршрутизация по типу карты, географии, сумме. Не требует реализации алгоритма, детерминирована и прозрачна. 
Отвергнута: не адаптируется к динамическому изменению характеристик провайдеров, требует постоянного ручного сопровождения.

**Weighted scoring с EMA (Exponential Moving Average)**

Детерминированная оценка провайдера на основе скользящего среднего успехов. Проще в реализации и отладке. 
Отвергнута: не решает дилемму exploration/exploitation — система неизбежно застревает на субоптимальном провайдере, не исследуя остальных.

**ε-Greedy**

Случайный выбор с вероятностью ε, лучший известный — с вероятностью (1-ε). Имеет теоретические гарантии сожаления. 
Отвергнут: ε — глобальный параметр, не зависящий от текущей неопределённости. При накоплении статистики exploration избыточен; при деградации провайдера — недостаточен.

**UCB (Upper Confidence Bound)**

Детерминированный алгоритм с теоретически оптимальным regret.
Отвергнут: плохо адаптируется к нестационарным условиям — доверительные интервалы рассчитаны для стационарного случая. В платёжных системах характеристики провайдеров меняются непредсказуемо.

**Contextual Bandit**

Учитывает характеристики конкретной транзакции (BIN карты, регион, сумма) при выборе провайдера. Теоретически превосходит MAB. 
Отвергнут для данного проекта: существенно сложнее в реализации и интерпретации, требует значительно большего объёма обучающих данных. Обозначен как направление дальнейшего развития.

## Последствия

**Стало лучше:**

Симуляция на T = 10 000 транзакций, 30 независимых запусков показала преимущество Thompson Sampling по ключевым метрикам:

| Метод | SR (стац.) | SR (после деград.) | Regret (стац.) |
|---|---|---|---|
| Thompson Sampling | 84.21% | 83.16% | 365.77 |
| Greedy | 83.70% | 81.50% | 433.34 |
| ε-Greedy (ε=0.1) | 83.45% | 82.57% | 453.03 |
| Round-Robin | 83.78% | 75.50% | 425.00 |
| Random | 83.85% | 75.64% | 425.68 |

Наименьший cumulative regret (365.77) и наименьшее падение success rate после деградации провайдера подтверждают практическую ценность метода.

Exploration/exploitation баланс достигается автоматически без настройки параметров — провайдер с малым числом наблюдений получает высокую дисперсию и органично исследуется.

**Принятые ограничения:**

Мультикритериальная функция оценки является эвристическим расширением классического Thompson Sampling. Теоретические гарантии regret доказаны для однокритериального случая; для предложенной функции они не исследованы. Метод остаётся обоснованным с практической точки зрения — стохастический компонент θᵢ сохраняет механизм исследования, детерминированные компоненты вносят наблюдаемые бизнес-критерии.

Значение γ = 0.99 выбрано эмпирически. При высоком RPS эффективное окно памяти может оказаться недостаточным — потребуется увеличение γ или адаптивная настройка в зависимости от интенсивности трафика.
